# Первый релиз v0.3.0 на GitHub — инструкция

Этот архив содержит **полный исходный проект**, а не только обновление. Нужен только GitHub Desktop и аккаунт GitHub. Windows EXE будет собран на серверах GitHub Actions.

## 1. Опубликовать проект

1. Распакуйте архив в отдельную папку `SeismicTravelTimePicker`.
2. Откройте **GitHub Desktop** и авторизуйтесь.
3. Выберите **File → Add local repository → Choose** и укажите распакованную папку `SeismicTravelTimePicker`.
4. Если появится предложение **Create a repository here**, создайте репозиторий с именем `SeismicTravelTimePicker`.
5. Сделайте первый коммит (кнопка **Commit to main**, если потребуется).
6. Нажмите **Publish repository**. Для публичного распространения снимите флажок **Keep this code private**.
7. На GitHub убедитесь, что в корне видны `README.md`, `main.py`, `requirements.txt`, `seismic_picker/` и `.github/workflows/windows.yml`.

**Не загружайте реальные данные клиентов:** `.sgy`, `.segy`, результаты пикирования, токены, пароли и `.venv`. Файл `.gitignore` защищает от стандартного добавления таких файлов, но содержимое репозитория всё равно стоит проверить перед публикацией.

## 2. Собрать Windows EXE

1. В браузере откройте опубликованный репозиторий и вкладку **Actions**.
2. Выберите **Windows EXE — Build and Release**.
3. После загрузки исходников workflow должен автоматически начать тесты и сборку. При необходимости нажмите **Run workflow** без флажка публикации.
4. Проверьте, что обе стадии проверки сборки завершились успешно. В завершённом запуске в разделе **Artifacts** можно скачать тестовый результат `SeismicTravelTimePicker-Windows`.

## 3. Опубликовать EXE в Releases

1. На вкладке **Actions → Windows EXE — Build and Release** нажмите **Run workflow**.
2. Выберите ветку **main** и включите параметр **Publish or update v0.3.0 in Releases with Windows EXE**.
3. Нажмите зелёную кнопку **Run workflow**.
4. После успешной сборки откройте **Releases → v0.3.0**.
5. В **Assets** появится `SeismicTravelTimePicker.exe`. Ссылка на Releases — то, что нужно отправлять пользователям.

Если возникает ошибка разрешений при создании Release, проверьте **Settings → Actions → General → Workflow permissions**, а также правила организации. Workflow запрашивает `contents: write` только для задания публикации.

## 4. Проверить готовый EXE

Скачайте EXE из Releases и откройте в Windows (в том числе Windows в Parallels). Проверьте открытие SGY, выделение пиков, расчёт Travel time, экспорт TXT/CSV и повторное открытие сохранённого проекта. **Пока сборка EXE на Windows не выполнена, работоспособность готового EXE не подтверждена**. Программа не подписана цифровой подписью, поэтому Windows SmartScreen может предупреждать о неизвестном издателе.

## Что не входит в архив

Реальные SEG-Y/SGY, виртуальное окружение Python, временные файлы PyCharm, пользовательские результаты. Исходный код версии v0.3.0 и руководство пользователя включены.
